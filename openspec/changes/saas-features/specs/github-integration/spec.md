# GitHub Integration

Capability: Configure GitHub repositories, export NPS categories and comments as GitHub issues with templates and labels, and track created issues.

## ADDED Requirements

### Requirement: GitHub repo configuration with validation

The system SHALL provide a GitHub configuration panel in project settings where the user can enter a repository owner, repository name, and personal access token (PAT). The system MUST validate the configuration by attempting to read the repository via the GitHub API.

#### Scenario: User configures a valid GitHub repository

WHEN the user enters a valid owner, repo name, and PAT with repo scope
AND clicks "Validate & Save"
THEN the system SHALL call the GitHub API to verify access to the repository
AND display a success message with the repository name and a green checkmark
AND persist the configuration encrypted in the github_configs database table.

#### Scenario: User enters an invalid PAT

WHEN the user enters a PAT that lacks the required repo scope or is expired
AND clicks "Validate & Save"
THEN the system SHALL display an error message indicating the token is invalid or lacks permissions
AND the configuration SHALL NOT be saved.

#### Scenario: User enters a non-existent repository

WHEN the user enters a repository owner/name combination that does not exist or is inaccessible
AND clicks "Validate & Save"
THEN the system SHALL display an error message indicating the repository was not found
AND the configuration SHALL NOT be saved.

### Requirement: Category-level export to GitHub issues

The system SHALL allow the user to export an entire category as a single GitHub issue from the dashboard. The issue MUST be created using the issue template and include aggregated data from all comments in that category.

#### Scenario: User exports a category to GitHub

WHEN the user clicks "Export to GitHub" on a category card
THEN the system SHALL create a GitHub issue with the category name as the title
AND the issue body SHALL follow the issue template including NPS impact, representative quotes, and recommendations
AND the issue SHALL be labeled with "nps-feedback" and the category name.

#### Scenario: User exports a category with no GitHub configuration

WHEN the user clicks "Export to GitHub" on a category card and no GitHub configuration exists for the project
THEN the system SHALL display a prompt directing the user to configure a GitHub repository in project settings.

---

### Requirement: Individual comment selection and batch export

The system SHALL allow the user to select individual comments from the data table and export them as GitHub issues. The user MUST be able to select multiple comments and batch export them as a single issue or as individual issues.

#### Scenario: User selects comments and exports as a single issue

WHEN the user selects 5 comments from the data table and clicks "Export as Single Issue"
THEN the system SHALL create one GitHub issue containing all 5 comments in the body
AND the issue title SHALL reflect the common category or "Multiple NPS Comments" if categories differ.

#### Scenario: User selects comments and exports as individual issues

WHEN the user selects 3 comments from the data table and clicks "Export as Individual Issues"
THEN the system SHALL create 3 separate GitHub issues, one per comment
AND each issue SHALL follow the issue template with the individual comment's data.

#### Scenario: User selects comments across multiple categories

WHEN the user selects comments from different categories and exports as individual issues
THEN each issue SHALL be labeled with its respective category name alongside the "nps-feedback" label.

---

### Requirement: Issue template with NPS impact, quotes, and recommendations

Every GitHub issue created from NPS data SHALL follow a standard template. The template MUST include: a summary section with NPS impact (number of comments, NPS score breakdown), a quotes section with representative verbatim comments, a recommendations section generated by the LLM, and metadata linking back to the NPS project.

#### Scenario: Category export issue template

WHEN a category with 25 comments (8 detractors, 10 passives, 7 promoters) is exported
THEN the issue body SHALL include:
- An NPS Impact section showing 25 comments with the score distribution
- A Quotes section with up to 5 representative verbatim comments
- A Recommendations section with AI-generated action items
- A metadata footer with a link back to the NPS project dashboard.

#### Scenario: Individual comment export issue template

WHEN a single comment with NPS score 3 and category "Performance" is exported
THEN the issue body SHALL include the full comment text, the NPS score, the category, and an AI-generated recommendation for addressing the feedback.

---

### Requirement: Labels include nps-feedback, category name, and type

Every GitHub issue created by the system SHALL include the label "nps-feedback." Category-derived issues SHALL also include a label matching the category name. The system SHALL add a "feature-request" or "bug" label based on the comment sentiment and content as determined by the LLM.

#### Scenario: Detractor comment about a bug is exported

WHEN a detractor comment describing a crash is exported as a GitHub issue
THEN the issue SHALL have labels: "nps-feedback", the category name, and "bug."

#### Scenario: Promoter comment suggesting a feature is exported

WHEN a promoter comment requesting a new feature is exported as a GitHub issue
THEN the issue SHALL have labels: "nps-feedback", the category name, and "feature-request."

#### Scenario: Labels that do not exist in the repository are created

WHEN the system attempts to apply a label that does not exist in the target repository
THEN the system SHALL create the label in the repository before applying it to the issue.

---

### Requirement: GitHub Issues tracker tab showing created issues with status

The project SHALL include a GitHub Issues tracker tab that displays all issues created from the project. The tracker MUST show the issue title, status (open/closed), labels, creation date, and a link to the issue on GitHub.

#### Scenario: User views the GitHub Issues tracker

WHEN the user navigates to the GitHub Issues tracker tab for a project with 12 created issues
THEN the system SHALL display a table listing all 12 issues with title, status, labels, creation date, and a clickable link to each issue on GitHub.

#### Scenario: Issue status is refreshed from GitHub

WHEN the user opens the GitHub Issues tracker tab
THEN the system SHALL fetch the current status of each tracked issue from the GitHub API
AND update the local status if it has changed (e.g., from open to closed).

#### Scenario: No issues have been created yet

WHEN the user navigates to the GitHub Issues tracker tab and no issues have been created
THEN the system SHALL display an empty state message explaining how to export categories or comments as GitHub issues.

---

### Requirement: Link back from issue to NPS project

Every GitHub issue created by the system SHALL include a metadata section in the issue body that links back to the NPS Insight Engine project. The link MUST include the project ID and the relevant dashboard view.

#### Scenario: User views a created GitHub issue

WHEN a user views a GitHub issue that was created from the NPS Insight Engine
THEN the issue body SHALL contain a footer section with a link back to the NPS project dashboard
AND the link SHALL include query parameters to highlight the relevant category or comments.
